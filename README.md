# dental-informed-consent-summary

把口腔医患沟通的转录文本，整理成结构化的《治疗方案与风险知情告知摘要》——一份可以直接打印给患者核对签字的纯文本三段式文书。

它只解决一件事：**录音转写完了，怎么把它变成一份能签字留痕的知情告知文书。**

## 为什么需要它

直接让模型总结一段医患沟通，通常会踩三个坑：

1. **替医生补话**——把自己的医学常识当成医生的告知内容写进风险条款。在知情告知文书里这是不能接受的。
2. **把患者的话记成医生的**——患者说"我听说这个很疼"，被写进了医生告知内容。
3. **格式漂移**——这次加粗、下次用圆点符号，打印出来的文书每次长得都不一样。

这个 Skill 用一张白名单、一张黑名单和一个机器自检脚本把这三件事挡住。

## 输入与输出

**输入**：一段医患沟通转录文本。完整对话、片段文字稿、助理的现场笔记都可以。

**输出**：纯文本三段式文书。

```text
一、患者基本情况
二、沟通中明确的治疗方案      ← 费用清单、治疗步骤、固定技术说明、签字栏
三、医患沟通中已提及的风险与不确定性
```

**核心约束只有一条**：凡是医生没说过的内容，都不写进文书。

该隐藏的条目（比如医生全程没提费用时的"费用清单"）会**整条连同标题消失**，不留占位符、不留空行。

## 安装

把整个目录放到你的技能目录下。以 WorkBuddy 为例，安装位置是 `~/.workbuddy/skills/`：

```text
~/.workbuddy/skills/dental-informed-consent-summary/
```

安装后重启或刷新会话即可生效。

## 怎么用

把医患沟通转录文本交给它，直接说：

- 把这段医患沟通整理成知情告知摘要
- 这是跟患者谈方案的录音转写，帮我出一份治疗方案告知书
- 这段沟通记录整理成签字用的告知书
- 帮我生成知情同意摘要，牙位和费用都按医生说的来

以下是**不应该**触发它的场景：写口腔科普或营销文案、写专科病历、整理内部会议纪要或患者投诉记录。

## 格式自检

生成完成后可以用自带脚本做一次机器校验：

```bash
python scripts/check_output.py 成品文件路径
```

脚本只读取文件，不做任何修改。检查项包括：是否混入了 Markdown 语法、`---` 分隔线数量、三个部分标题是否齐全且单独成行、签字栏是否完整、技术说明固定话术是否被改写、方括号占位是否替换干净、是否用了禁用列表符号、费用清单是否带了固定附注。

退出码：`0` 通过，`1` 存在必改项，`2` 文件不可读。仅依赖 Python 标准库，支持 Python 3.10 及以上。

## 内容边界

**允许补充的只有三项**：治疗必要性的中性说明（限 1-2 句）、显微镜技术说明的固定话术、STA无痛麻醉作为麻醉选项。

**明确禁止六项**：补充医生没提过的风险/并发症/概率数字；新增原文没有的治疗方案、药物、材料；修改、弱化或遗漏医生的明确结论；对成功率或疗效做任何承诺性表述（技术说明除外）；虚构患者姓名性别年龄、费用金额、牙位编号；把患者的陈述或家属的发言误记为医生告知内容。

**遇到以下情况会停止生成，而不是硬凑**：转录文本不足 50 字、通篇是单方自述、完全没有医生告知性发言、沟通内容不涉及治疗决策（例如常规洁牙和复查）。

## 免责声明

本 Skill 产出的是**文书草稿**，用于降低整理成本，不能替代执业医师的审核与判断。

知情告知文书涉及法律效力与医疗责任，交付患者签字前必须由经治医生逐字复核，并结合实际临床情况修改。使用者对最终文书内容负责。

另外请注意：**不要把真实的患者转录文本上传到公开仓库**。Skill 包内不含任何患者数据，但使用时产生的文书属于患者隐私，请留在本地。
